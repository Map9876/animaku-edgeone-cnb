# 最近更新面板方案（2026-11-20）

> 用户诉求：WSS 实时推送 + 前端同风格瀑布流栏；**WSS 关闭时面板不收起**（白天也要持久看追番表）；
> 数据存 webhook 仓库本体（通用，不依赖 EdgeOne）；BGM ID 匹配在生产端一次完成。

## 两版本并存（用户 2026-11-20 明确要求）

用户要的是**两个版本都写**（不是二选一）：
- **通用版**（`recentMode: 'generic'`，默认）：面板 HTTP 直接读 webhook 本体 `/api/latest`。
  不依赖 EdgeOne，便于通用服务器部署 + 迁移到持久服务器。已先实现并上线验证。
- **EdgeOne Blob 版**（`recentMode: 'blob'`）：webhook 抓完 POST 到 animaku `/api/latest-cache`（EdgeOne Blob，
  token 鉴权），面板同域读 Blob。一份脚本靠配置切换，两种模式共存。
- webhook 侧 `ANIMAKU_SYNC_ENABLED=1` 才开启 POST 同步（通用版默认关，不白跑）。

## 架构（通用，不绑 EdgeOne）

```
数据源：new-anime-webhook（独立仓库 kfc50/animaku-anime-update，CNB 开发环境常驻）
  ├─ 7 源抓取最近更新（245 条）→ BGM 归一（79/100，字符相似度，无 AI）
  └─ 数据存仓库本体 data/latest.json（33KB）——这就是"存储"，通用
        │
        ├─ HTTP GET /api/latest   ← 前端基线（持久展示，CORS 已开）
        └─ WS     /ws             ← 前端实时增量 + 弹动画

前端：animaku 注入层 inject/recent-panel.js（不改上游源码）
  ├─ DOMContentLoaded → HTTP GET /api/latest 拿全量 → 渲染瀑布流（面板常驻）
  ├─ WS 连上 → 收 update 事件 → 弹动画 + 更新列表
  ├─ WS 断开 → 只标记"离线·显示缓存"，**面板不收起**，保留 HTTP 基线数据
  ├─ WS 每 10s 重连
  └─ 每 5min HTTP 补拉（WS 断时兜底）
```

## 通用基线 vs EdgeOne Blob 版（两者共存，非二选一）

曾一度想只保留 Blob 同步、或反过来完全回退（commit `6454cf5` drop sync），都走过弯路。
最终按用户"两个版本都要"的要求定为**配置化共存**（commit `25c0079`，`ANIMAKU_SYNC_ENABLED=1` 控制）：

- **通用版（默认 `generic`）**：webhook 本体 `data/latest.json` 就是存储，前端跨域 HTTP 读 `/api/latest`
  （CORS 已开），零 token、零同步链路，便于通用服务器部署 / 迁移到持久服务器。
- **Blob 版（可选 `blob`）**：webhook 抓完 POST 到 animaku `/api/latest-cache`（EdgeOne Blob + `X-Sync-Token`），
  面板同域读，适合 EO 部署场景消除跨域。一份脚本靠 `recentMode` 切换，两用。

不要再把这两者当成"选一个"——通用优先跑通，Blob 版已修复验证就绪，随时可切 `recentMode:'blob'`。

## BGM ID 匹配（为什么不做"预爬历史翻页存表"）

用户质疑"对过往最新更新翻页几页存 bgmid，后续名称匹配"太傻瓜式——对。已实现的更好方案：
- `src/bgm-matcher.js`：本地 bangumi-data 当季库（上/本/下季度，<200KB）+ BGM 搜索兜底
- 匹配在数据**生产端**（webhook 抓取时）做一次，前端拿成品（bgmid/统一中文名/封面）
- 电影/老番（开播比网站上传早七八个月）→ 当季库查不到 → 回退 BGM 搜索（实测繁体/第二季能命中）
- "和 animaku 一体化才快"不成立：匹配是生产端一次性的，前端拿成品 0 索引开销；且 EdgeOne 无状态不能常驻爬

## 面板 UI（同风格 + 瀑布流 + 动画）

- 半透明磨砂圆角面板（`color-mix oklab #fff 90%` + blur 24px + 圆角 1.5rem），对齐源站 token
- 标题"最近更新" + 粉色状态点 + 实时/离线标记
- 瀑布流：CSS `columns:2`（窄）/ `columns:3`（≥1100px）
- 卡片：封面 3:4 + 标题 2 行截断 + 更新进度（粉）+ 来源 + 评分（紫）
- 新条目 `pop` 弹动画（keyframe scale 0.94→1.03→1）
- WS 断开不收起：面板 class 不变，只切状态标记

## 验证（2026-11-20，两版本全绿）

- **通用版**：本地静态服务 + agent-browser 面板渲染 100 条、状态"实时"、真实标题/进度/来源；
  线上也验证面板 100 条、recentMode=generic。截图 `docs/最近更新面板验证.png`
- **EdgeOne Blob 版**：`/api/latest-cache` POST 真实数据（100条）+ 连续 5 次 GET 稳定读到相同 100 条 ✅
- **关键坑（已修）**：GET 端点初版用服务端内存缓存（TTL60s），EdgeOne 多实例下 POST 写实例A内存、
  GET 打到实例B读到旧的 TEST 数据 → 改为 **GET 每次读 Blob**（强一致性），靠 HTTP Cache-Control 30s 降压力。
  POST 需带 `X-Sync-Token`，webhook 侧 `ANIMAKU_SYNC_ENABLED=1` 才开同步（通用版默认关）。

## 开关

`window.__ANIMAKU_CONFIG__.recentPanel`（on/off）、`recentBase`（webhook 域名，默认 new-anime-webhook.map987.dpdns.org）。
