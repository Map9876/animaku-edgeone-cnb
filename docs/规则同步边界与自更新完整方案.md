# 规则同步边界与自更新完整方案

> 基于真实源码分析（2026-11-18），讲清楚"我们到底同步了什么、能自更新什么、不能自更新什么"，
> 以及"别人一键部署后如何也能完整自更新"。不夸大、不误导。

---

## 1. Animaku 的源解析是两层，不是一层

Animaku **不依赖 kazumi**，全部自己实现。源解析分两层：

| 层 | 内容 | 在哪 | 数据 or 代码 |
|---|---|---|---|
| **A. 搜索 / 章节列表** | `searchURL`、`searchList`(XPath)、`chapterResult`、`referer` 等 | `apps/web/src/data/default-plugins/*.json`（17 个） | **数据（JSON）** |
| **B. 播放链接 resolve** | AES-256-GCM 解密、HMAC 派生密钥、challenge 流程等 | `apps/server/src/lib/{bimi,xifan-next,...}.ts`（12 个） | **代码（TS，编译进 bundle）** |

证据：`lib/bimi.ts:359` 用 `createDecipheriv(AES-256-GCM)` + HMAC-SHA256 派生密钥解密播放地址，
这套逻辑是 100+ 行硬编码函数，不在 JSON 里。

---

## 2. 我们当前同步的是哪层

`runtime/rules-store.ts` 只 fetch 17 个 `default-plugins/*.json` → Blob，运行时覆盖前端规则。

- ✅ **A 层能自更新**：源站换了搜索接口/域名（改 `baseURL`/`searchURL`/XPath）→ JSON 同步能修
- ❌ **B 层不能靠 JSON 自更新**：源站改了播放页加密方式 → JSON 修不了，必须改 TS 源码重新打包

**所以"规则自更新"的准确表述是：搜索/章节层自更新，播放解析层仍需重新打包。**

---

## 3. 为什么 B 层做不到"只同步数据"

1. 播放解密是**编译进 bundle 的函数**，不是可独立下载的 JS。
2. 它依赖大量内部上下文（`fetchPublic`、SSRF 防护、密钥派生、challenge 流程），不是能塞进 Blob 的独立脚本。
3. EdgeOne 函数里 `eval`/`new Function` 动态执行外部代码：① 平台限制 ② 冷启动/安全成本 ③ 源站代码本身不可独立提取。
4. Animaku 没有"规则订阅"机制（不像 kazumi 能订阅别人写的规则）——它所有解析都是自己代码。

**结论：想让播放解析也"换数据就更新"，上游架构不支持，我们也不该用动态执行去硬凑。**

---

## 4. 别人一键部署后，如何也能完整自更新

关键区分"部署方式"：

| 部署方式 | A 层（搜索/章节） | B 层（播放解析） | 谁能用 |
|---|---|---|---|
| **上传静态包**（index.html + assets + bundle） | ✅ JSON 自更新 | ❌ 冻结在 bundle | 我们验证过，简单 |
| **绑仓库构建**（EdgeOne/CNB Provider=Cnb，push 触发 CI） | ✅ | ✅ CI 重新打包全量更新 | 想要完整自更新必须用这个 |

**唯一能让别人也完整自更新的路**：让别人**也用我们的 CI 模式**——
fork `kfc50/animaku-edgeone` → EdgeOne 项目绑定该仓库（Cnb/GitHub 类型）→ push 触发
`.cnb.yml`：submodule update → build → 部署。这样播放解析代码跟我们一起更新。

我们仓库已经具备这套能力（`.cnb.yml` + 规则自更新 + CI 回写），别人只需"绑仓库"而非"传静态包"。

---

## 5. 对原作者的对接建议（保持稳定协议）

我们依赖的"路径契约"是：
```
https://raw.githubusercontent.com/uerax/Animaku/master/apps/web/src/data/default-plugins/*.json
```
只要这个目录名和 JSON 字段（`baseURL`/`searchURL`/`searchList` 等）不变，A 层自更新永久有效。
这种约定式路径对开源项目相当稳定，但值得跟作者要个明确承诺。见 `docs/给原作者的issue-规则路径协议.md`。

**不要求作者提供解密接口**——解密是他自己的核心代码（反爬能力的护城河），不会开放。我们要的只是
"规则 JSON 的路径和格式保持兼容"，这是低成本、合理、作者也乐意的请求。

---

## 6. 一句话总结

- Animaku 解析分两层：搜索/章节（JSON 数据）+ 播放解密（TS 代码）。
- 我们同步 JSON → 搜索/章节能自更新；播放解密不能靠 JSON，必须重打包。
- **别人想完整自更新，必须绑仓库走 CI，不能只传静态包**——我们仓库已支持。
- 跟作者要的是"规则路径/格式稳定"的承诺，不是解密接口。
