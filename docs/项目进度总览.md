## 一、项目本质（一句话）

不改 Animaku 上游源码（git submodule 只读 + 注入层 + 构建期 esbuild 改写），
叠加统计、自更新、UI 增强等能力，通过 CNB CI 自动跟随上游更新并部署到 EdgeOne。
上游随便改，我们 `submodule update --remote` 自动吸收，**零 fork 冲突**。

## 三、架构

```
uerax/Animaku master (GitHub 上游)
  │  submodule（只读，指针跟最新）
  ▼
CNB 仓库 kfc50/animaku-edgeone (main)
  │  push → CI (.cnb.yml)
  │  node:22 + corepack pnpm@9.15.0
  │  git submodule update --remote → 拉上游最新
  │  build-edge.mjs / build-resolvers.mjs / sync-web.mjs / inject-into-html.mjs
  │  ci-commit-artifacts.sh（产物回写，[skip ci] 防循环）
  ▼
webhook → EdgeOne Pages (CNB 类型项目)
  ├─ cloud-functions/api/[[default]].js  (4.5MB 后端 bundle)
  ├─ resolvers/parsers.cjs / public/resolvers  (16 源 TS 解析包)
  ├─ assets/ + public/  (v1.30.5 前端静态，双份镜像)
  ├─ public/inject/  (ui-inject.js / analytics.js 注入层)
  └─ middleware.js  (SPA fallback)
```

## 四、已完成的功能（按时间线）

### 1. 部署打通（404/502 根因）
- 404 静态：根目录 + `public/` 双份静态资源，无论 EdgeOne 取哪个根都命中
- 502 API：两个真凶——undici（cheerio 1.2 间接依赖，CJS 在 EdgeOne 崩）和 sharp（原生 libvips 无二进制）→ 用 esbuild alias stub 掉，**上游源码零改动**
- SPA fallback：middleware.js 把非 API/非静态路径 rewrite 到 index.html，解决 `/subject/:id` 等 404
- 本地 dev 能跑但线上崩的教训：CNB→EdgeOne 只上传 bundle 单文件、不带 node_modules

### 2. 规则自更新（A 层，JSON）
- `runtime/rules-store.ts`：按 name 从 EdgeOne Blob（`animaku-rules/rules.json`）读最新规则；无/过期则 fetch `raw.githubusercontent.com/uerax/Animaku/master/.../default-plugins/*.json`（17 源）写 Blob，TTL 1 小时
- 构建期注入 `parseRuleOrThrow`，前端传过时规则会被 Blob/GitHub 最新同名规则覆盖
- 验证：传 `baseURL:WRONG.invalid` 搜「咒术回战」仍返回稀饭网正确结果 4 条

### 3. TS 解析代码远程热更新（B 层）
- `scripts/build-resolvers.mjs` 把 16 源 `lib/*.ts`（含 AES-256-GCM 解密）打包成 `resolvers/parsers.cjs`（3.2MB）
- `runtime/parser-loader.ts` fetch parsers.cjs → `new Function(require,module,exports,code)` 动态加载 → 按导出键名找源函数 → 动态优先、内置回退
- 已改成**动态 origin**（不写死域名，从当前请求 host 拼 URL）
- 验证：`/api/__parsers` 16 源加载成功；搜索 diagnostics 含 `[parser-loader:remote]` 标记

### 4. 注入 UI
- 底部胶囊导航：**逐字抄** next.xifanacg.com 编译产物（5 个 Phosphor SVG path、圆角 24px / bg .9 / blur 24px / brand #cd7083），不是手写近似
- 紧凑信息密度：CSS 覆盖上游大间距，开关 `compact`
- 已删除用户不要的"白色风格"按钮；Git 同步面板沿用统一设计风格
- 设置页"定时从 GitHub 更新"开关是**展示性**的（存 localStorage），真正更新由 CI 做

### 5. CI 工具链修复（版本卡 v1.30.2 根因）
- 根因：CI 用 node:20 且无 pnpm，`sync-web.mjs` 的 pnpm 失败被 catch 静默吞掉 → 一直用旧 v1.30.2 dist
- 修复：`.cnb.yml` 改 node:22 + corepack pnpm@9.15.0 + 加 build-resolvers + sync-web 失败改 exit(1)
- 验证：CI 日志 `✓ built in 6.19s`，线上更新到 v1.30.5

### 6. P0 排行榜（自有统计）
- 上游 rank API 依赖 SQLite，EdgeOne 无状态下恒空 → 前端 `HomeLeaderboards.tsx:207` 数据空时 `return null`
- `runtime/analytics.ts` 加 `/api/stats/rank*` 路由（优先于上游 SQLite 版），从 Blob 事件按 subjectId 聚合 `{bangumiId,totalPlayCount}`
- 验证：写入播放事件后 rank 返回真实数据，浏览器截图确认"观看排行（日/周/月榜）+ 观看总榜"完整渲染

### 7. 统计体系（自有）
- `/api/track` 写 EdgeOne Blob，`/api/stats` 聚合 utm/entry/页面流转/subject/小时趋势
- 前端 analytics.js 已埋：utm、did、路由跳转、搜索、换源、进入详情

## 五、决策与边界（重要）

| 事项 | 结论 |
|---|---|
| 权重/合榜算法 | **不自己写**，交给 `bangumi-rank` 项目（已有播放速率+贝叶斯口径）|
| 源站播放量（爬第三方）| 暂缓，原站自己都没做；要做只能当统计页 tab，非一级页面 |
| 对上游提 PR | 暂缓，后续还要加更多钩子，现在提会被推翻 |
| GitHub webhook 实时推送 | 过度设计，榜单半小时才变，定时抓+静态 JSON 足够 |
| GET-UPLOAD / CNB 临时域名 | 限 10 IP + 18h 变，不适合；动态 IP 用 Cloudflare Tunnel 破 |
